# DiPlay 运行日志云存储

在「设置 → 诊断」手动输入 COS 桶名、Endpoint、SecretId 和 SecretKey，或导入本机 JSON。
导入后默认关闭上传，需要明确打开「上传运行日志到 COS」。JSON 使用下列结构，**占位符不是密钥**：

```json
{
  "bucket": "example-1234567890",
  "endpoint": "cos.ap-guangzhou.myqcloud.com",
  "secretId": "<enter-on-device>",
  "secretKey": "<enter-on-device>"
}
```

建议为车机创建只允许 `Logs/com.shihab.diplay.cn/*` 执行 `cos:PutObject` 的独立凭据。
在车机上导入的配置保存在应用私有的 `noBackupFilesDir`，仓库不包含实际凭据；
私有构建若使用下述内置配置，APK 会包含该配置。设置界面不回显已保存的密钥。
请勿把真实配置 JSON 放进本仓库或附在诊断报告中。

## 构建时内置配置
私有构建可以把一份默认配置直接编进 APK：放在仓库根的 `.local-cos/diplay-cos.json`
（已在 `.gitignore` 中），或用 `DIPLAY_COS_CONFIG` 指向任意路径。
首次启动时它写入本机设置并立即替换内置默认值，之后以车机上保存的值为准，包括把上传开关关掉。
JSON 里 `"enabled": true` 表示安装后直接开始上传，无需在设置里再打开。

内置的 SecretKey 可以从 APK 中提取，因此只应使用仅允许 `cos:PutObject` 的独立密钥，
并在密钥泄露时立即轮换。

## 从 U 盘自动读取
在「设置 → 诊断」点「U 盘配置目录」，用系统文件选择器选中 U 盘根目录一次，DiPlay 会持久化这次授权。
之后把同一份 JSON 放在该目录（推荐文件名 `diplay-cos.json`，其他 `.json` 也可以），
插上 U 盘或重新打开 DiPlay 就会自动读取并保存配置，无需再点任何按钮。

- 只读取 U 盘，不写入、不删除；单个文件上限 16 KiB，最多尝试 4 个 JSON。
- 导入不会打开上传开关，也不会覆盖驱动程序在车机上手改过的同一份配置（内容相同即跳过）。
- 导入会替换已保存的凭据；开关保持原状，所以上传已开启时只在信任该 U 盘来源的情况下使用。
- 换一个 U 盘或换目录时，再点一次「U 盘配置目录」即可；旧授权随之弃用。
- 部分车机的文件选择器不显示 U 盘，此时仍可用「导入 COS 配置 JSON」手动选择文件。
- 自动读取只在本进程存活期间进行（插盘时或打开 App 时）；App 被彻底杀掉后需要重新打开一次。

启用后，进程存活期间每 60 秒上传一次**未压缩**的纯文本。分别上传
`diplay.log`（CarPlay 会话）、`iccoa-link.log`（ICCOA 与 USB/BLE 链路）、
`carplay-connection.log`（CarPlay 从点击到首帧的时间线）。每个对象只含对应来源新增的日志行：
`Logs/<应用包名>/YYYY-MM-DD/HH-mm-ss-<起始偏移>-<来源文件名>`。

上传的是会话日志里"上次成功上传之后"新增的部分，因此：

- 失败不丢：COS 未返回 HTTP 200 时偏移不前进，下一分钟重试同一段，直至成功。
- 不重复：成功后偏移前移，已上传的行不会再传。
- 不打包：没有 gzip、没有待传目录、没有 128 MiB 队列，本地日志文件本身就是重试队列。
- 每次重试最多取 256 KiB；长时间离线后积压的日志会按分钟逐块补齐。
- 日志重置/轮转导致文件变短时，偏移归零，只上传新内容。

停用开关会立即停止上传，并把偏移移到文件末尾；重新启用后不会补传停用期间写入的行。

这里只上传 DiPlay 自身保存的三类连接日志。ICCOA 链路文件会采集本应用可见的 ICCOA SDK logcat 行；不会上传完整系统 logcat 或 CarsBridge 私有数据。
已脱敏仍不意味着日志完全匿名；开启上传前应确认目标桶由自己控制。
